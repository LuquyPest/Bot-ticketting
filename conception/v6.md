# Conception — v6 : fiabilité, compléments et plusieurs espaces

> Statut : **validé** par le mainteneur le 19 novembre 2026 (« fait tout sauf les trucs avec de l'IA dedans »). Ce document fixe le périmètre et le découpage en pull requests ; il est mis à jour par une PR quand une décision change.

## 1. Le but

La v5 a fait de Datick un centre de services complet. La v6 ne change pas de cap ; elle :

- **fiabilise** ce qui tourne déjà : contrôles automatiques dans la CI, connexions à la base dimensionnées, diagnostic des fonctions Discord ;
- **termine** ce que les PR de la v5 ont laissé de côté (écarts notés dans chacune) ;
- permet de travailler sur **plusieurs espaces** à la fois, à la manière des entités de GLPI, sans fusionner leurs bases ;
- rend le dashboard **installable sur téléphone** ;
- **explique** la v5 à ceux qui viennent d'un autre outil.

**Hors périmètre** : toute aide par IA (réponse proposée, résumé, classement) ; inventaire et parc, CMDB, contrats, fournisseurs, budgets, réservations, gestion de projet ; application mobile native (la PWA en tient lieu).

## 2. Ce qui ne change pas

Les engagements des v4 et v5 valent pour chaque PR : une instance en v5 passe en v6 sans rien faire ; Discord, l'e-mail, le web, le widget et l'API restent des canaux de même rang ; l'API v1, v2, v3 et les webhooks ne cassent pas ; chaque PR est livrable seule, testée, documentée en français et en anglais, avec sa ligne de patchnotes et sa revue de sécurité ; rien d'obligatoire.

## 3. Décisions

### 3.1 Fiabilité

- **Analyse statique dans la CI** : ESLint (variables et composants non définis, clés en double, code inatteignable) sur le serveur et le dashboard ; un échec bloque la fusion.
- **Corps malformés** : la suite d'intégration envoie des tableaux, objets, nombres et chaînes très longues aux routes publiques et du staff ; aucune ne doit répondre 500.
- **Connexions à la base** : taille du pool réglable par variable d'environnement (`DB_POOL_SIZE` pour la base globale, `DB_TENANT_POOL_SIZE` par espace), valeurs par défaut relevées ; la page Santé montre les connexions utilisées.
- **Diagnostic Discord** (Instance → Santé, et par espace) : pour chaque serveur, les permissions du bot (gérer les salons, les rôles, les messages, les fils), les catégories et salons configurés qui n'existent plus, la place du rôle du bot par rapport aux rôles qu'il attribue. Lecture seule. Une liste de vérifications manuelles complète la doc.

### 3.2 Compléments de la v5

- **Images dans les articles** de la base de connaissances : envoyées depuis l'éditeur, stockées comme les pièces jointes (taille et types limités, noms tirés au hasard), servies avec l'article selon sa visibilité.
- **Règles** : conditions sur l'**organisation** du demandeur et sur les **champs personnalisés** ; action **appliquer une politique SLA**.
- **Inactivité et escalade** deviennent des règles temporelles : les réglages actuels sont repris en règles équivalentes à la migration (même effet), l'écran actuel renvoie vers les règles.
- **Imports** : option « mettre à jour ce qui est déjà importé » (contacts, organisations, articles ; les tickets gardent leur historique, seuls statut et priorité changent).
- **Rétention** : bouton « appliquer maintenant » (fondateurs) qui traite tout ce qui est dû, par lots.

### 3.3 Annuaire

- **Synchronisation programmée** des contacts et organisations (chaque heure, chaque jour ou à la main), qui **met à jour** les fiches déjà importées.
- **Comptes créés à la connexion**, en option : une personne du groupe autorisé qui n'a pas encore de compte en reçoit un, avec l'adresse de l'annuaire, et rejoint les espaces choisis avec le rôle choisi (support par défaut). Désactivé par défaut.

### 3.4 Plusieurs espaces

Chaque espace garde sa base. La v6 ajoute :

- **Vue multi-espaces** : une page « Tous mes espaces » liste les tickets ouverts de tous les espaces où l'on fait partie du staff, chacun filtré par les droits qu'on y a ; un clic ouvre le ticket dans son espace.
- **Modèle d'espace** : un nouvel espace peut reprendre la configuration d'un espace existant (statuts, sujets, champs, SLA, règles, catalogue, modèles de réponse), avec l'export et l'import de configuration déjà là.

### 3.5 Mobile

**PWA** : manifeste, icônes, écran de lancement, installation depuis le navigateur, raccourcis (tickets, nouveaux tickets), page hors ligne. Les notifications push existent déjà.

### 3.6 Faire connaître

- Guides : **venir de GLPI**, **venir de Zendesk ou Freshdesk**, **mettre en place un SLA**, **brancher son Active Directory**.
- README et page d'accueil de la documentation présentés comme un centre de services complet, Discord compris.

## 5. Sécurité

- Images des articles : types d'image seulement (pas de SVG), taille plafonnée, nom aléatoire, en-têtes `nosniff` et `Content-Disposition`, servies seulement si l'article est visible du lecteur.
- Vue multi-espaces : chaque espace interrogé avec la session et les droits qu'on y a ; rien n'est lu dans un espace dont on n'est pas staff.
- Comptes créés par l'annuaire : seulement pour le groupe autorisé, option coupée par défaut, journalisés dans le journal de l'instance.
- Diagnostic Discord : lecture seule, réservé au propriétaire de l'instance (et aux fondateurs pour leur espace).
